# CUDA executor

`libcere_executor.so` implements ABI v5 ([../README.md](../README.md)) for one model kind, `CERE_MODEL_QWEN4_EXP_NVFP4` (A4), on one Blackwell GPU (compute capability 12.0, code for `sm_120a` only). M2.2a delivers model creation, upload and instantiation on GPU0 and every kernel proven against an in-container oracle; the forward pass, sessions that generate and SMOKE are M2.2b.

Slot selection (ABI v5, `cere_slot_selection`; ABI v4's `cere_levers`): the K2 small-M GEMM (`k2_gemm` = `CERE_LEVER_K2_SMALL_M`) and the P4 tensor-core prefill attention (`prefill_attention` = `CERE_LEVER_PREFILL_P4`, `kernels/p4_attention.h`) are compiled into every library and selected per model at INSTANTIATE and on `cere_model_set_selection` (`model::apply_levers`: `GemmPlan::use_small_m` on every plan the model owns, `Workspace::prefill_p4` for K6/K9); the defaults (all 0) run cuBLASLt for every M and the CUDA-core attention kernels, byte-identical to the pre-lever default library (`executor/tests/gpu/test_levers_off_identity.py`, suite `levers`). Every buffer a selection reads is carved at ALLOCATE whatever the selection, so a swap between requests allocates nothing. `draft_tokens` caps the host's verify window; `decode_step` GRAPH is `CERE_ERR_UNSUPPORTED`; `moe_gemm` only checks the compiled `CERE_MOE_BACKEND`, which stays a build variant.

## Seams

| Directory | Contents | CUDA includes |
|---|---|---|
| `src/host/` | ABI entry points (`api.cpp`), state machine (`state.*`), compiled A4 support table (`support.*`), KV pool plan check and page allocator (`kv_pool.*`, M2.5), the `cere::host::Device` interface (`device.h`), export maps | none |
| `src/toy/` | CPU toy device for CI (`make test-executor-host`) | none |
| `src/device/` | CUDA device: context, eager-loading check, bounce ring, memory plan (`memory_plan.*`, pure arithmetic shared by estimate and allocate), ALLOCATE/UPLOAD/INSTANTIATE | yes |
| `src/kernels/` | kernels and their host launch APIs (one family per file, below) | yes |
| `src/ktest/` | `cere_ktest_*` entry points (device pointers + stream) exported only by `libcere_ktest.so`, called by the oracles through ctypes | yes |

`device.h` is the swap seam: the host layer drives one `Device` (estimate, allocate, write, instantiate, sessions, one greedy step), and a kernel family can be replaced behind its launch API and re-checked by the same oracle file.

## Paged KV pool (M2.5)

- One pool per model in the device arena, after the session slots (`src/device/memory_plan.h`): per full-attention layer (12) FP8 E4M3 K and V `[pool tokens, 512]` and BF16 QSA compressed keys `[pool tokens / 4, 128]` (`src/model/layout.h:140-154`, `src/model/model.h:249-252`); at 200,000 tokens that is 12 × (2 × 200,000 × 512 + 50,000 × 256) = 2,611,200,000 B [computed from `layout.h`]. A page is 64 tokens (`src/host/kv_pool.h:13`) and one page id covers every layer.
- Pool size: `cere_model_desc.kv_pool_tokens`, 0 = `max_sessions` × ceil(`max_context_tokens` / 64) × 64; non-zero a multiple of 64, ≥ the context and ≤ the support table's `max_kv_pool_tokens` 1,048,576 (`src/host/kv_pool.h:18-24`, `src/host/support.cpp:96-97`: context 262,144, the model's `max_position_embeddings`, and pool 1,048,576, ctx262 design note CX-01).
- `host::PagePool`, sized at ALLOCATE and guarded by `slots_mutex_`, hands out the lowest free page ids in ascending order. `create_session` reserves ceil(the session's `max_context_tokens` / 64) pages; on a shortfall it returns `CERE_ERR_CAPACITY` with nothing kept, so `step` never fails for pages. It then writes the session's slot map (int64 `[max_context_tokens]`, logical position -> `page × 64 + offset`) once on device (`session_set_pages`); K6/K9 address KV through it. Destroying the session returns its pages; pages are never zeroed (a session reads only its own positions' slots) (`src/device/cuda_device.cpp:116-120`, `:345-397`). No eviction, page sharing or prefix cache (M2.10).
- GDN/conv/PLE state and the QSA pending ring stay in the fixed per-session slot (`src/model/layout.h:113-138`).
- Memory at 200,000 on GPU0 (R1 probe, native-probe-20261010T214358Z-warm.json): capabilities `kv_pool_tokens` 200,000 and `kv_page_tokens` 64, executor peak 78,581 MiB, free at peak 18,341 MiB (within the 80 GiB executor limit and the 10,240 MiB free floor; no limit raise).

## Eager, preallocated, no JIT

- Executor creation requires `CUDA_MODULE_LOADING=EAGER` in the process environment (checked with `cuModuleGetLoadingMode`; lazy loading is `CERE_ERR_UNSUPPORTED`), so every module of the library, its own kernels and cuBLASLt's, is resident before the first model is created (O14).
- Creation also makes the cuBLASLt handle and pins the bounce ring (4 slots × 64 MiB, one stream each; one slot per concurrent `cere_model_put` caller or M2.11 snapshot/restore copy).
- ALLOCATE takes the whole memory plan in one `cudaMalloc` (DEVICE tensors in arena order, the workspace, the derived tensors, `max_sessions` session slots, the paged KV pool; `src/device/memory_plan.h`) and one `cudaHostAlloc(cudaHostAllocMapped)` (HOST_PINNED tensors: the PLE table, scale and index; the workspace's staging). INSTANTIATE drains the device and checks for errors. After INSTANTIATE nothing is allocated and no module is loaded.
- The device accepts two support entries: `a4_support` (the text-only desc, `vision_config` null) and `a4_vision_support` (the text entry's limits plus `vision_config` equal to the compiled A4 vision tower and the 333 `model.visual.*` BF16 DEVICE tensors; m213 design note D9, D10, m213l design note VL-L1). Only a vision plan adds the image buffers (sized for one image of 4,096 merged rows: 50,331,648 B patches, 20,971,520 B embeddings, 20,971,520 B `Workspace::image_out`, the prompt's three-axis positions) and the encoder plans (D12), encodes each image in every PREFILL call (chunk) that holds its rows, before layer 0 (spliced embeddings; three-axis positions in K1, K6 and the K9 `indexer_qk_mrope`/`qsa_compress_store_mrope` twins), rotates every row past the prompt at position + `rope_delta` (the rotary table base `cos_sin + rope_delta × 64` in eager decode, rows, verify and MTP launches; the decode, rows, verify and draft graphs only when every row's `rope_delta` is 0) and reports `native_image_input` (capability 61); a text-only plan and every text session's launches are unchanged.
- The M2.11 snapshot arena (`cere_model_desc.snapshot_host_bytes` > 0) is not in the mapped block: ALLOCATE takes it as its own `host::LockedMemory` (`src/host/locked_memory.h`: page-aligned anonymous `mmap`, zero-filled, `MADV_DONTDUMP` + `MADV_DONTFORK`, `mlock`ed; zeroed, unlocked and unmapped with the model), never device-mapped nor CUDA-registered, so it takes no GPU memory. The host estimate is the mapped block plus the arena (`memory_plan.h` `pinned_bytes`). A failed `mmap`, `madvise` or `mlock` (`RLIMIT_MEMLOCK` below the arena without `CAP_IPC_LOCK`) is `CERE_ERR_CAPACITY` with the reason and the bytes needed on stderr; nothing is kept. Snapshot and restore stage through a leased ring slot on the executor stream (`CudaDevice::stage_to_host` / `stage_to_device`): save gathers the state runs D2H into one 32 MiB half while the CPU copies the other, landed half into the arena; restore copies the arena into one half while the other half's H2D scatter runs.
- Memory ledger (`src/host/memory_ledger.h`, M2.11 R1 [REVISED 2026-10-11]): the device records the exact bytes it holds from its own allocations, by kind: the ring (creation), and per model the ALLOCATE `cudaMalloc` (its only device allocation), the mapped block and the arena's locked pages, each dropped when freed. cuBLASLt's and the CUDA context's own memory are not in it. The ktest `cere_ktest_model_ledger` reads it; K15 gates R1 on it instead of `cudaMemGetInfo`/`MemAvailable`.
- No Triton, NVRTC or other JIT in the library; FlashInfer, SGLang and FLA run only as oracles inside the container.

## Link

Static `cudart_static`, `cublasLt_static` and `culibos` from the image's toolkit; `-Wl,--build-id=none`, `-Wl,--strip-all` (no `.symtab`: nvcc's per-PID `tmpxft_*` file names would otherwise differ between builds) and `-ffile-prefix-map` for byte-reproducible output; `-fvisibility=hidden` with version scripts (`src/host/exports.map`: the ABI functions; `src/host/ktest_exports.map`: `cere_ktest_*`); `-Wl,-z,defs`, so an unresolved symbol fails the link instead of `dlopen`. `build.json` records flags, the source tree hash, output SHA-256 and `NEEDED`; `scripts/check_third_party.py` rejects anything not in `../THIRD_PARTY.json`.

These are correctness kernels (one row, eager, one stream). Replacing a family with a library kernel (FlashInfer, CUTLASS, chunked GDN) or adding CUDA graphs is an M2.3 change, profiled and re-checked by the same oracle and parity gates.
