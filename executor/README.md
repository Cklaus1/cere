# Native executor boundary

`include/cere_executor.h` is the versioned executor ABI (`CERE_EXECUTOR_ABI_VERSION` 5). C11 and C++17 compile checks (`make test-c`) assert every struct size, field offset and constant and dump the layout, which must equal `tests/fixtures/executor_abi_v5_layout.json`; the Rust projection compares its offsets with that file. Capabilities belong to a model/profile, not a global CUDA device; they report the actual `execution_mode` (native, backend_managed, serial, unsupported), carry `u64` decode batch bounds like the `execution_capabilities` schema, and an `operations` bitmask.

Every allocation/session/ticket carries an owner epoch; completion tickets also carry the model generation. Cancellation is intent, the terminal poll is the memory-release boundary. Pointer lifetimes are documented beside the fields: descriptors and input token IDs are copied before return; output buffers are leased until the terminal poll. Host calls are serialized per executor, except `cere_model_put`, which may run concurrently for different tensors between create and seal; asynchronous completion uses tickets. Transport of opaque handles between processes requires a separate validated protocol, not sending raw pointers.

## ABI v5 migration

ABI v5 is a breaking change from ABI v4 (SelfTune ST2, selftune design note D3/D4, Q5(a)): the perf levers become a versioned slot-selection block that the registry (`crates/cere-runtime/src/levers.rs`, `tests/fixtures/lever_registry.json`) maps one to one. Every selection still picks a kernel or path at run time in the one library, with the same values and defaults as v4.

- `cere_levers` is removed. `cere_model_desc.levers` (offset 120) becomes `selection`, a pointer to a `cere_slot_selection` (400 bytes: `struct_size`, `abi_version`, `block_version` = `CERE_SLOT_BLOCK_VERSION` (1), `count`, then `choices[CERE_SLOT_MAX]` (16) of `cere_slot_choice` {`slot`, `impl`, `params[CERE_SLOT_PARAMS]`} (24 bytes)), copied by `cere_model_create`. The slots are `CERE_SLOT_K2_GEMM` (1) .. `CERE_SLOT_K2_WEIGHTS` (7), in the v4 field order; `impl` takes the v4 `CERE_LEVER_*` values, and `CERE_SLOT_DRAFT_TOKENS` has the one impl `CERE_LEVER_DRAFT_WINDOW` (0) with the window in `params[0]` (0 = the model's `speculative_draft_tokens`). A slot not listed is at its default; null is every slot at its default, v4's null `levers`.
- `cere_model_desc` grows from 128 to 136 bytes: `family` (offset 128: the struct `config` points at; `CERE_FAMILY_QWEN4_EXP` = 0 with a `cere_qwen4_exp_config`, and since ST4 S3a `CERE_FAMILY_SDAR` = 1 with a `cere_sdar_config` and `model_kind` `CERE_MODEL_SDAR_BF16`; a library accepts only the family it was built for, any other value is `CERE_ERR_UNSUPPORTED`) and `calibrate_windows` (offset 132, `CERE_CALIBRATE_ALL` = 0 / `CERE_CALIBRATE_MTP` = 1, the former `cere_levers.calibrate_windows`; a create-time choice, not a slot, so the hot swap cannot touch it).
- Validation (create and hot swap alike): a bad header, a `block_version` other than 1, a `count` above `CERE_SLOT_MAX`, a slot outside 1..`CERE_SLOT_COUNT` or listed twice, an unknown `impl`, or a non-zero param an impl does not take is `CERE_ERR_ARGUMENT`; a known choice the library or model cannot run is `CERE_ERR_UNSUPPORTED` (as v4: a MoE backend other than the compiled one, a draft window on a model without drafts, below 2 or above its `speculative_draft_tokens`).
- The two lever functions keep their export positions under new names: `cere_model_selection(executor, model, out)` reads the active selection back (every slot listed once, in slot order; the caller sets `out` struct_size/abi_version) and `cere_model_set_selection(executor, model, selection)` replaces it between requests (`CERE_ERR_BUSY` with a ticket in flight; `k2_weights` stays fixed at create, so another value is `CERE_ERR_UNSUPPORTED`; on error the selection is unchanged).
- A v4 caller is refused cleanly: its 128-byte desc fails the struct_size check (`CERE_ERR_ARGUMENT`) and `abi_version` 4 in any struct is `CERE_ERR_UNSUPPORTED`; `cered` refuses a v4 library at load (`abi_version`).
- Layout fixture: `tests/fixtures/executor_abi_v5_layout.json` (renamed from v4).

## ABI v4 migration

ABI v4 is a breaking change from ABI v3 (the PerfInt lever registry, `crates/cere-runtime/src/levers.rs`, the single source of truth for every perf lever): one `libcere_executor.so` carries every kernel selection and the profile's `[deployments.native.levers]` picks them per model at run time, instead of CMake options per library.

- `cere_model_desc` grows from 120 to 128 bytes: `levers` (offset 120) points at a `cere_levers` (40 bytes: `struct_size`, `abi_version`, `k2_gemm`, `prefill_attention`, `decode_step`, `moe_gemm`, `draft_tokens`, `verify_attention`, `k2_weights`, `calibrate_windows`), copied by `cere_model_create`; null is every field 0, the defaults and v3's behaviour (`CERE_LEVER_K2_CUBLASLT`, `CERE_LEVER_PREFILL_CUDA_CORE`, `CERE_LEVER_DECODE_EAGER`, `CERE_LEVER_MOE_BUILD`, draft_tokens 0 = the model's `speculative_draft_tokens`, `CERE_LEVER_VERIFY_PER_ROW`, `CERE_LEVER_K2_WEIGHTS_BF16`). A v3 caller's 120-byte desc is `CERE_ERR_ARGUMENT` (struct_size), a v3 `abi_version` stamp `CERE_ERR_UNSUPPORTED`. `verify_attention` (m23 design note P11R-19) took the former `reserved` field's offset: `CERE_LEVER_VERIFY_BATCHED` runs a VERIFY chain's full-attention rows as one K6 prologue and one attention launch, bit-identical to the per-row calls.
- Validation (create and hot swap alike): a bad `cere_levers` header or an unknown value is `CERE_ERR_ARGUMENT`; a known value the library or model cannot run is `CERE_ERR_UNSUPPORTED`: a `moe_gemm` other than `CERE_LEVER_MOE_BUILD` and the compiled backend (`CERE_LEVER_MOE_P3B` in a `CERE_MOE_BACKEND=p3b` library, `CERE_LEVER_MOE_K7` in a k7 one; the toy device is a p3b build), and `draft_tokens` non-zero on a model without drafts, below 2 or above its `speculative_draft_tokens` (a speculation round then drafts at most `draft_tokens - 1`; greedy output is unchanged). `decode_step` is `CERE_LEVER_DECODE_EAGER`, `CERE_LEVER_DECODE_GRAPH` (P1: eligible plain decode steps replay a CUDA graph) or `CERE_LEVER_DECODE_SPEC_GRAPH` (that plus VERIFY and the MTP draft-extend/draft steps replayed from per-shape CUDA graphs), all bit-identical.
- New exports, appended after `cere_model_host_resident`: `cere_model_levers(executor, model, out)` reads the model's active levers back (caller sets `out` struct_size/abi_version; every lever field is written); `cere_model_set_levers(executor, model, levers)` replaces a sealed model's active set between requests (`CERE_ERR_BUSY` while any ticket of the executor is in flight; on error the set is unchanged). Every lever but `k2_weights` selects only which kernel or path runs over the same weights, layout and buffers: ALLOCATE carves the buffers every selection needs, so a swap allocates nothing.
- `k2_weights` (Fp8W, offset 32; the struct grew from 32 to 36 bytes) is the one lever that changes the weights: `CERE_LEVER_K2_WEIGHTS_BF16` (0, default) keeps the checkpoint's BF16 dense weights; `CERE_LEVER_K2_WEIGHTS_FP8` (1, numerics-changing, opt-in) makes INSTANTIATE quantize the attention qkv/o/indexer, GDN in_proj qkv/z/b/a and out_proj, shared-expert gate/up/down and lm_head projections in place to E4M3 with one FP32 scale per output row, which K2 then runs on the FP8 small-M kernel (m <= 16) or dequantized (m > 16). It is fixed at `cere_model_create`: a value above `CERE_LEVER_K2_WEIGHTS_FP8` is `CERE_ERR_ARGUMENT`, and `cere_model_set_levers` with a `k2_weights` other than the model's is `CERE_ERR_UNSUPPORTED` (nothing changes); `cere_model_levers` reads it back. The registry lists it as a restart-class lever.
- `calibrate_windows` (LoadCrit LC-01, load-crit design note, offset 36; the struct grew from 36 to 40 bytes) selects no kernel and changes no output: how deep `cere_model_seal` times the adaptive policy's spec-round cost table. `CERE_LEVER_CALIBRATE_ALL` (0, default and every null desc) times every window the plan can pick, as before; `CERE_LEVER_CALIBRATE_MTP` (1) times windows 1..4 only and prices 5..16 from window 4 by the prior shape, for a caller whose tickets never set `CERE_WORK_TAIL_DRAFTS`/`LONG`/`CHAIN` (those alone price windows past 4). A value above `CERE_LEVER_CALIBRATE_MTP` is `CERE_ERR_ARGUMENT`; it is fixed at `cere_model_create`: `cere_model_set_levers` ignores the caller's value and keeps the model's (`cere_model_levers` reads it back). cered sets it from the `drafter` lever (mtp / lookup / mtp+lookup: MTP; the tail, long and chain drafters: ALL).
- Removed build options: the CMake `CERE_K2_SMALL_M` and `CERE_PREFILL_ATTENTION` options, their compile definitions and build.json `flags.k2_small_m` / `flags.prefill_attention` are gone (`native_dev.py build` has no `--k2-small-m` / `--prefill-attention`); the K2 small-M GEMM and the P4 prefill attention are in every library. `CERE_MOE_BACKEND` stays a build variant.
- Layout fixture: `tests/fixtures/executor_abi_v4_layout.json` (renamed from v3; ABI v5 renamed it `executor_abi_v5_layout.json`).

## ABI v3 migration

ABI v3 is a breaking change from ABI v2 (`CONTRIBUTING.md`: breaking changes carry a migration note):

- `cere_model_load(executor, manifest_path, out)` is removed. A model is created in three stages that follow the artifact load stages: `cere_model_create(executor, desc, out)` validates a `cere_model_desc` (model kind, a typed `cere_qwen4_exp_config`, the tensor table with dtype, placement `DEVICE`/`HOST_PINNED`/`DISCARD`, rank and shape, `max_sessions`, `max_context_tokens`, model stop tokens) against the compiled support table and the memory budgets and allocates; `cere_model_put(executor, model, tensor_index, offset, bytes, len)` copies tensor bytes (concurrently for different tensors); `cere_model_seal(executor, model)` checks exact tiling and instantiates.
- `cere_work` gains caller-owned output buffers leased until the terminal poll (`out_tokens`, `out_capacity`, optional `out_scores` with `cere_token_score` top-2 entries) and per-item `stop_token_ids`/`stop_token_count`.
- `cere_completion` gains `finish` (`CERE_FINISH_NONE`, `LENGTH`, `STOP_TOKEN`, `CANCELLED`, `ERROR`); `committed_tokens` is published with release ordering and never decreases.
- `cere_execution_capabilities` gains `operations` (`CERE_OPS_PREFILL`, `CERE_OPS_DECODE`, `CERE_OPS_VERIFY`, `CERE_OPS_CANCEL`), so identity checks compare operations.
- `cere_executor_abi_version()` returns the library's ABI version before any other call.
- Status codes are documented per case in the header; struct sizes changed for `cere_execution_capabilities` (72), `cere_work` (112) and `cere_completion` (48).
- v3.L frame (ledger L0, native-abi-ledger design note): the four shared structs take their final v3 layout, `cere_execution_capabilities` 88, `cere_model_desc` 120, `cere_work` 168 and `cere_completion` 64 bytes. `cere_work.reserved` is `flags` (`CERE_WORK_*`; a bit outside `CERE_WORK_KNOWN_FLAGS` is `CERE_ERR_ARGUMENT`, bit 0 `CERE_WORK_IGNORE_STOP_TOKENS` (M2.12) makes no stop token finish the ticket and is `CERE_ERR_ARGUMENT` on VERIFY, bit 1 `CERE_WORK_NO_SPECULATION` is a no-op), `cere_model_desc.reserved` is `speculative_draft_tokens`, `cere_completion.reserved` is `cached_tokens`, and capability bytes 57-61 are named. Every field whose owner has not landed must be zero/null (else `CERE_ERR_UNSUPPORTED`) and reads 0 on output. One size per struct: a `struct_size` other than `sizeof(T)` of the header is `CERE_ERR_ARGUMENT`; `CERE_EXECUTOR_ABI_VERSION` stays 3.
- M2.7 sampler (ledger table N): `cere_sampling_params` (88 bytes, flags `CERE_SAMPLING_KNOWN_FLAGS` = 0), `cere_logit_bias` (8), `cere_logprob_entry` and `cere_token_logprobs` (176, up to `CERE_MAX_TOP_LOGPROBS` = 20 alternatives) are defined; `cere_work.sampling`/`out_logprobs`/`top_logprobs` take them and capability `native_sampler` reports the device sampler. Null/0 is the greedy path, unchanged.
- Image input (M2.13, ledger N): `cere_image_input` (80 bytes) and `cere_qwen4_exp_vision_config` (80 bytes) have bodies, plus `CERE_ACT_GELU_TANH`; `cere_model_desc.vision_config`, `cere_work.images`/`image_count` and capability byte 61 `native_image_input` are live (rules in `docs/EXECUTION_PLUGIN.md`). A text-only caller keeps them null/0 and sees no change.
- M2.11 snapshot/restore (m211 design note D1-D14, v3.L, no struct size change): `cere_model_desc.snapshot_host_bytes` reserves one host arena at ALLOCATE (counted in the host estimate; 0 = off, the shipped default; on the CUDA device its own page-aligned `mlock`ed allocation outside the mapped host block, not CUDA-registered: [cuda/README.md](cuda/README.md#eager-preallocated-no-jit)), and `CERE_OPS_SNAPSHOT`/`CERE_OPS_RESTORE` and `native_state_snapshot` are set exactly when it is non-zero. `cere_session_snapshot` copies an idle session (no ticket in flight, else `CERE_ERR_BUSY`) into the arena as a `CERESNP1` image (kinds 0-8: token ids, every per-session device section and, kind 8, the M2.7 sampler's `out_counts` (ledger CR13); first-fit, 256-B aligned; no room: `CERE_ERR_CAPACITY`); `cere_session_restore` loads it into a fresh session of the same model (non-fresh or too short: `CERE_ERR_ARGUMENT`/`CERE_ERR_CAPACITY`) and the restored session continues bit-exactly; `cere_snapshot_get_info`/`cere_snapshot_read` export the bytes, `cere_snapshot_import` validates untrusted bytes (D14) into the arena, `cere_snapshot_release` frees the range. Model release refuses while a snapshot exists (`CERE_ERR_BUSY`). Every entry is `CERE_ERR_UNSUPPORTED` on a model without an arena. Kernel-test entries `cere_ktest_session_*`, `cere_ktest_state_digest`, `cere_ktest_model_memory` (K15, `executor/tests/gpu/test_model_k15_snapshot.py`).
- Kind 11 snapshot (M2.13 C14, ledger CR14): an image session's `CERESNP1` image adds kind 11, its mRoPE `rope_delta` (i64, 8 B, 256-B aligned, after kind 8); text sessions keep kinds 0-8. `layout_id` covers kinds 0-8 and 11. Restore/import refuse a `rope_delta` outside (-position, 0] (`CERE_ERR_ARGUMENT`) and kind 11 on a model without vision (`CERE_ERR_UNSUPPORTED`); a restored image session decodes at position + `rope_delta`.
- Long image prompts (M2.13-L, m213l design note VL-L1..VL-L7; ABI v4, `cere_image_input` grows to 80 bytes, no other struct change): `cere_image_input.pixel_sha256` (offset 48) is the SHA-256 of the item's `pixel_bytes`, copied with them; all-zero is `CERE_ERR_ARGUMENT`. A PREFILL may carry up to 32 images of up to 4,096 merged rows each (16,384 patches), anywhere in a prompt up to the session context; NO_SPECULATION is no longer required and no `indexer_budget` bound applies, so image sessions draft (MTP and lookup) and take the prefix cache when namespaced. An image session's pad rows are keyed in the cache by words of SHA-256(`pixel_sha256` ‖ grid t/h/w), every other row by its token id (text unchanged); a session restored from a snapshot has no keys and runs cache-off. The prompt's rows use mRoPE positions everywhere (K1/K6 and the K9 indexer and compressed keys); every row past the prompt rotates at position + `rope_delta` (the rotary table base shifted by `rope_delta` × 64 in eager decode, verify and MTP launches; CUDA graphs only when every row's `rope_delta` is 0, so text launches are unchanged). Images are encoded per prefill call that holds their rows and freed after the prompt. Tests: `tests/host/test_state.cpp` `test_image_long_prompt`, `test_image_rows_and_drafts`, `test_prefix_image_keys`, `test_prefix_image_end_state`, `test_vision_support_values`; GPU `executor/tests/gpu/test_model_vl43_long.py`.
- M2.5 paged KV (native-abi-ledger design note table D 72, table C 72/80; m25 design note D2, D4): `cere_model_desc.kv_pool_tokens` (offset 72) is the KV pool in tokens. 0 is the derived pool, `max_sessions` × ceil(`max_context_tokens` / 64) × 64 (every session gets its full context); non-zero must be a multiple of 64 and ≥ `max_context_tokens` (else `CERE_ERR_ARGUMENT`) and ≤ the support table's `max_kv_pool_tokens`, 1,048,576 for A4 (ctx262 design note CX-01; a validation bound, the memory estimate refuses a pool the device cannot hold) (else `CERE_ERR_UNSUPPORTED`) (`cuda/src/host/kv_pool.h:18-24`, `cuda/src/host/api.cpp:238-244`). `cere_execution_capabilities.kv_pool_tokens` (offset 72) reports the pool the model allocated and `kv_page_tokens` (offset 80) the page, 64 (`cuda/src/host/api.cpp:531-532`). `cere_session_create` reserves ceil(the session's `max_context_tokens` / 64) pages and returns `CERE_ERR_CAPACITY` with nothing kept when fewer are free ([cuda/README.md](cuda/README.md#paged-kv-pool-m25)).
- M2.8 vocab masks (m28 design note A1-A6, D9; ledger W 136/144, C 58, F bit 1, X, CR5, CR7, CR22; no struct size change, ABI version stays 3): `cere_work.vocab_mask` (offset 136) / `vocab_mask_words` (offset 144) carry the item's initial mask, copied before return. `vocab_mask_words` 0 = unconstrained (`vocab_mask` null); otherwise it must equal ceil(vocab / 32), `sampling` must be non-null and the mask non-null and allow at least one id below vocab, else `CERE_ERR_ARGUMENT` (also for a null mask with non-zero words or a non-null mask with 0 words). Bit layout is xgrammar's: id j is allowed iff `(mask[j >> 5] >> (j & 31)) & 1`. `cere_executor_constrain(executor, ticket, position, vocab_mask, vocab_mask_words)` (A2) sets the mask of the ticket's next token, copied before return: `CERE_ERR_ARGUMENT` when `position` is not the ticket's committed count, for wrong words, an all-zero mask or an unconstrained ticket; `CERE_ERR_STALE_EPOCH` and unknown tickets exactly as `cere_executor_poll`. A poll advances a ticket in the order cancel, length, then, for a constrained ticket without the mask for `committed`, `CERE_PENDING` with nothing stepped; otherwise one step with that mask, which is then cleared (D9), so a constrained ticket commits at most one token per poll (CR22). Under M2.6 rounds a constrained ticket awaiting its mask is not decode-ready and no other ticket's poll steps it (CR5). VERIFY on a constrained item is `CERE_ERR_ARGUMENT` (CR7). The sampler stage sets disallowed ids to -inf after the penalties and before `logit_bias` (the CUDA device uploads the mask into a 31,040 B carve of the K12 sampler scratch; an unconstrained item passes no mask, so its path is unchanged); the toy's own greedy rule replaces a masked `next` by the smallest allowed id above it, wrapping. Capability `native_token_mask` (offset 58, A3) is 1 exactly when `native_sampler` is.
- M2.9 native speculation (m29 design note C1-C5, C9, D1-D9, I1-I4, M29S2-*; ledger C 54/59, D, F bit 1, W; no struct size change, ABI version stays 3): `cere_model_desc.speculative_draft_tokens` is 0 or 4 (else `CERE_ERR_UNSUPPORTED`, as is a draft the device cannot run) and `draft_token_map` is set exactly then (1..vocab strictly increasing ids below vocab, else `CERE_ERR_ARGUMENT`). Such a model reports `native_speculative_batch` 1, `speculative_draft_tokens` 4 and `CERE_OPS_VERIFY` when the library has a forward pass. A session drafts iff its PREFILL lacks `CERE_WORK_NO_SPECULATION` (bit 1, read per ticket; image work may draft since M2.13-L). **Speculation rounds:** each decode round batches the tickets of drafting sessions into one device `speculate_rows`: a row verifies the session's last token plus up to 3 pending MTP proposals (fewer when the budget `min(max_new_tokens - committed, context left)` is short; none for a `NO_SPECULATION` DECODE, a stop-ignoring or a constrained ticket), commits the accepted prefix plus the model's own next token (greedy: the plain argmax chain, so outputs and scores equal a plain run; sampled: D6 accept/resample on ledger M8 channels 4-5/6-7 keyed by position, so the distribution equals plain sampling), truncated after the first stop token and at the budget, then runs draft-extend for the next proposals (also after a 0-draft row, D9). Plain sessions of the same model step through `step_rows` in the same round. `cere_completion.verify_steps` counts the rounds and `accepted_drafts` the accepted proposals. **VERIFY** (`CERE_OP_VERIFY`): 1-3 caller drafts on a decode-ready drafting session, one round, then LENGTH unless a stop token ended it; on a model without draft `CERE_ERR_UNSUPPORTED`; on a non-drafting session, or with bit 0, bit 1 or a mask, `CERE_ERR_ARGUMENT`. **Rollback (D7):** a device failure before a row's commit consumes nothing (the ticket ends ERROR with nothing committed in that round); one in draft-extend after the commit publishes the committed tokens on that poll and ends the ticket ERROR at the next round. Snapshots of a drafting model add kind 10 (the session's MTP state and pending proposals) and its `layout_id` covers kind 10; a model without draft writes kinds 0-8 (and 11) and keeps its `layout_id`. Tests: `tests/host/test_state.cpp` `test_spec_*`, `tests/host/test_library.cpp` `speculating_round_trip`.
- M2.9L suffix-lookup drafts (m29l design note D1-D5; ledger F bits 2 and 3; no struct size change, ABI version stays 3): `CERE_WORK_LOOKUP_DRAFTS` (bit 2) lets a drafting ticket verify host suffix-lookup drafts. These are the tokens that followed the longest earlier occurrence (3 to 32 tokens) of the session's current suffix in its prompt and committed tokens (`host/spec_lookup.{h,cpp}`, `SuffixDrafter`). With the bit set, a per-request `DraftPolicy` picks MTP, lookup or none each round. It goes by expected committed tokens per unit of round cost, priced by the same fixed table as bit 4 below (batch-concurrency design note BC-D4: the model's `round_costs` for its `k2_gemm` lever, for greedy and sampled tickets alike, so a seeded ticket draws the same tokens alone and as one of several rows; the model-wide EMA of single-row `speculate_rows` wall time that priced non-adaptive tickets before BC-D4 is deleted). `CERE_WORK_NO_MTP_DRAFTS` (bit 3) never verifies MTP proposals; draft-extend still runs every round. The picked drafts take VERIFY's caller-draft path, so greedy output equals plain decode and sampled output keeps the target distribution. `CERE_WORK_KNOWN_FLAGS` is `0xF`. Bits 2 and 3 are a no-op on a ticket that never drafts and `CERE_ERR_ARGUMENT` on VERIFY. `cere_ktest_generate_flags` is the kernel-test generate with a `cere_work.flags` value; it also reports verify steps and accepted drafts.
- M2.9A adaptive draft policy (m29a design note A2; ledger F bit 4; no struct size change): `CERE_WORK_ADAPTIVE_DRAFTS` (bit 4) lets a drafting ticket's session `DraftPolicy` pick each round's MTP draft count (0..3; with bit 2 also the source) from the request's own acceptance, priced by the fixed table of the model's `k2_gemm` lever (median single-row round ms by window; O95, m23 design note SC-01: measured at `cere_model_seal` on the loaded library by `host/spec_calibrate.{h,cpp}` for the model's own `k2_gemm` value and the windows its levers can pick (the other value's table stays `SpecCosts::untimed()`), kept for the life of the load and logged as one `cere: spec_round_costs` stderr line; `SpecCosts::untimed()` on a device that does not time its rounds), so the picks depend only on the token stream and reruns pick the same windows. VERIFY with bit 4 is `CERE_ERR_ARGUMENT`. `CERE_WORK_KNOWN_FLAGS` is `0x1F`.

- M2.16 load time (m216 design note L1, L3, L4; ledger X; no struct size change, ABI version stays 3): a `DISCARD` tensor needs no `cere_model_put` (the seal checks tiling only for `DEVICE`/`HOST_PINNED`), so the caller never reads its bytes. ALLOCATE no longer pins the private host block synchronously: it maps it and a background pinner populates and `cudaHostRegister`s it while UPLOAD writes into it; for an attached shared segment the pinner registers the region and verifies its content digest in parallel. `cere_model_seal` joins the pinner first, and a pin or digest failure fails the seal (the model stays unsealed). `cere_model_host_resident(executor, model, tensor_index, out)` returns the read-only bytes of a HOST_PINNED tensor of an unsealed model whose host region was attached from a published segment, covering the tensor as a put would; `CERE_ERR_UNSUPPORTED` for a private or creating region. Device-id option `host_share_keep=1` (only with `host_share`) keeps the published segment after the last clean detach (removal: `docs/RUNBOOK.md` "Warm restart and the segment lifecycle").

- M2.16 put staging (m216 design note M216S-11/12; ledger X; ABI v4, no struct change, appended after `cere_model_set_levers`): `cere_executor_register_staging(executor, base, bytes)` pins a caller range (CUDA: `cudaHostRegister`), and a DEVICE `cere_model_put` whose source lies wholly inside a registered range is DMA'd straight from it on one of 16 staged streams instead of through the 4 × 64 MiB bounce ring; `cere_executor_unregister_staging(executor, base)` ends it (`CERE_ERR_BUSY` while a put from it is in flight; destroy is `BUSY` while any range is registered). Callers treat both symbols as optional. The private or shared host region is registered in 1 GiB pieces from the end of ALLOCATE, so ALLOCATE's and UPLOAD's CUDA calls interleave with the background pin.

- m210 D15⁗′ stage 2a prefix end states (ledger X: appended to ABI v4 after `cere_executor_unregister_staging`, the put-staging precedent, no struct change): `cere_model_set_prefix_end_state(executor, model, on)` before the model's first ticket (`CERE_ERR_BUSY` after) lets a drafting cache-on PREFILL also capture its state at floor64(n − 1) inside its cold prefill call (two pool slots, class = that call's length), which an equal-class repeat resumes bit-identically to its cache-off run. Off by default; on only in the opt-in `-v22` profile (O112: the pair is freed only from end states and the capturing session's own states below its deepest one, m210 design note D15⁗′ eviction); callers treat the symbol as optional.
- m210 D17 prefix alternative edges (appended to ABI v4 after `cere_model_set_prefix_end_state`, no struct change): `cere_model_set_prefix_alt_edges(executor, model, on)` before the model's first ticket (`CERE_ERR_BUSY` after) lets a session whose tokens the tree already holds over other sessions' pages (a conversation sharing a header with a cached one, diverging before its first state) insert its states on an alternative edge over its own pages instead of being refused (M210S-39), so both conversations keep hitting; lookups take the deepest state over all alternatives. Every state still covers only its own session's KV rows (hits stay equal to the cache-off run). Off by default; on only in the opt-in `-v51` profile; callers treat the symbol as optional.
- Prefix cache counters (appended to ABI v4 after `cere_model_set_prefix_alt_edges`, optional symbol index 32; the `cere_prefix_stats` struct, 104 bytes): `cere_model_prefix_stats(executor, model, out)` copies the model's cumulative `PrefixStats` into `*out` (`hits`, `captures`, `capture_skipped`, `capture_page_mismatch` (M210S-39 refusals), `inserts`, `state_evictions`, `leaf_evictions`, `host_spills`, `host_loads`, `host_drops`, `alt_edges`, plus `alt_edges_on`). It is a plain read: no tree walk, no allocation, no state change. It follows the host-call serialization like every other call (a caller never overlaps it with a submit/poll/cancel of the same executor) and may run with tickets in flight, because rounds run only inside `cere_executor_poll`. The counters start at 0 at the model's creation, never decrease (`cere_model_flush_prefix_cache` keeps them) and are not persisted. `struct_size` other than `sizeof(cere_prefix_stats)` or a null `out` is `CERE_ERR_ARGUMENT`, a wrong `abi_version` `CERE_ERR_UNSUPPORTED` (both leave `*out` untouched); a model created with `prefix_state_slots` 0 is `CERE_ERR_UNSUPPORTED` with the body zeroed. `cered` shows it on `GET /v1/cere/prefix_cache` and the cards; a library without the symbol gives no counters (never an error).
- Prefix capture sites and lost hits (prefix-token design note PT0a; appended to ABI v4 after LoRA's `cere_session_set_lora`, optional symbol index 40; the `cere_prefix_capture_stats` struct, 48 bytes): `cere_model_prefix_capture_stats(executor, model, out)` copies the split of `capture_skipped` by site, `skipped_prefill_slot` (a prefill capture found no slot), `skipped_decode_track` (a session's decode track capture found no slot: counted once per ticket, though every later 64-token boundary of the ticket retries) and `skipped_end_pair` (an end-state capture found no slot pair), whose sum is `capture_skipped`; plus `hit_shortfall_tokens` (per drafting lookup, the tokens between its hit and the deepest prefill-chunk multiple its page match passed, where no draft state was) and `hit_shortfall_lookups` (the lookups that lost any). Same contract as `cere_model_prefix_stats` (header checks, `CERE_ERR_UNSUPPORTED` with `prefix_state_slots` 0, a plain read allowed with tickets in flight); a library without the symbol gives no site counters (never an error).

- GrammarSpec constrained speculation (grammar-spec design note GS-01/GS-02; ledger X and CR7 amendment: appended to ABI v4 after `cere_executor_set_prefill_slice`, optional symbol indices 34 and 35, the `cere_model_set_prefix_end_state` precedent, no struct change): `cere_executor_round_drafts(executor, ticket, position, drafts, capacity, count)` freezes the drafts of a constrained ticket's next round (at most `CERE_MAX_CONSTRAINED_DRAFTS` = 3) while it awaits the mask of `position`. `cere_executor_constrain_drafts(executor, ticket, position, drafts, draft_count, vocab_masks, vocab_mask_words)` then gives `draft_count + 1` masks for a prefix of them, and the round verifies row j under its own mask: greedy output is bit-identical to masked plain decoding. A speculation row's `sampling->vocab_mask` is row 0 of those masks (CUDA: `verify_sample_stage` uploads row j's mask before its `process`; the toy reads row i). Used only under cered's opt-in lever `grammar_drafts = "on"` (profile `-v49`); callers treat both symbols as optional, and the pre-staging toy lacks them.

- Track LoRA adapters (lora design note; appended to ABI v4 after `cere_executor_constrain_drafts`, optional symbol indices 36 to 39, no struct change): `cere_model_lora_reserve(executor, model, max_adapters, max_rank)` before seal carves a device pool (counted against `memory_budget_bytes`); `cere_model_lora_load` / `cere_model_lora_unload` fill and free a slot on the sealed model (`CERE_ERR_BUSY` while a live session uses it); `cere_session_set_lora(executor, session, slot)` binds a session before its first submit. An adapter adds `s * B (A x)` (double-float sums, one rounding) to the full-attention q / k / v / o and shared-expert gate / up / down projections; the MTP layer stays base-only, rows without an adapter run the base bits, and a session with an adapter takes no snapshot. Opt-in only in the `-v50` profile; callers treat the symbols as optional.

ABI v2 (breaking vs v1): `decode_batch_min`/`decode_batch_max` widened to `uint64_t`, `execution_mode` added to `cere_execution_capabilities`, `model_generation` added to `cere_completion_ticket`.

## Host layer, devices and builds

- `cuda/src/host/` is the ABI v5 implementation without CUDA includes: the executor/model/session/ticket state machine (epochs, generations, submission IDs, cancel as intent, terminal-poll release, destroy refusing while work is in flight), model-desc validation against the compiled A4 support table, and the concurrent-`put` tiling ledger. It drives one `cere::host::Device` (`cuda/src/host/device.h`: estimate, allocate, write, instantiate, sessions, one step of one session that is greedy or, given an `ItemSampling`, sampled, one decode step of several sessions as rows, each row greedy or sampled with its own `ItemSampling`). `cuda/src/host/sampler_ref.{h,cpp}` is the CPU sampler reference (M2.7 C2: penalties, `logit_bias`, top_k/top_p/min_p mask, counter-RNG draw, logprobs) that the toy device uses and `tests/host/test_sampler.cpp` checks against the SGLang oracle cases.
- `cuda/src/toy/` is a CPU device with a deterministic toy model (next = (31·last + position) mod vocab; with sampling, small synthetic logits drawn through `sampler_ref`; device-id options `,prefill_chunk=N`, `,sampler=0` reports no sampler, `,record=<abs path>` appends one numbers-only line per executed step). `make test-executor-host` builds `build/host/libcere_executor_toy.so` and the variant without a forward pass `build/host/libcere_executor_toy_noforward.so` (`CERE_TOY_NO_FORWARD`) with `c++`, checks that they export exactly the ABI functions, and runs `tests/host/*.cpp`; `make test-rust` exports their absolute paths as `CERE_TOY_EXECUTOR` and `CERE_TOY_EXECUTOR_NOFORWARD`.
- `CMakeLists.txt` builds, inside the pinned image only (`scripts/live/native_dev.py build`), `libcere_executor.so` (host layer + the CUDA device under `cuda/src/device/` + kernels under `cuda/src/kernels/`) and `libcere_ktest.so` (kernels + `cere_ktest_*` entry points under `cuda/src/ktest/`) for `sm_120a`, with static cudart/cuBLASLt/culibos, no build ID, mapped source paths, hidden visibility and version scripts (`cuda/src/host/exports.map`, `ktest_exports.map`), then writes `build.json` (provenance, flags, source tree hash, output hashes and `NEEDED`). Sources are globbed; while `cuda/src/device/` or `cuda/src/ktest/` has no source, the project still configures and that library's target fails the build with a message naming the directory.
- Rows (M2.6, m26 design note D1-D7): a model's plan `max_sessions` (R ≤ 16: the A4 support table's `max_sessions`, m23 design note P8; m26 D3 was 4) is its decode row count; caps report `decode_batch_min` 1, `decode_batch_max` R and `native_decode_batch` 1 when R > 1 (`native_mixed_prefill_decode` stays 0). One ticket per session, `item_count` 1; rows form across tickets. Each `cere_executor_poll` runs at most one executor-wide round, then reports the polled ticket: a **prefill round** runs one chunk (≤ 4,096 tokens, the m22c chunk boundaries; with `prefill_slice_ms`, one layer segment of it) of one ticket with unconsumed prompt (`Device::step` reports `*consumed`; the session is decode-ready after its last chunk). Without a decode share the ticket is the runnable one (not finishing, not waiting on an older ticket feeding a shared prefix, `prefix_wait`) with the fewest prompt tokens left, ties to the oldest; one overtaken `prefill_age_calls` times (default 8, `cere_executor_set_prefill_age`) by younger tickets' calls runs next (`next_prompt`, batch-concurrency design note BC4 lever (b)); with a decode share the oldest prompt goes to `share_round`. Prefill calls run back to back in a run of at most as many calls as the round has prompt tickets (and, with a slice, at most one slice of wall time); a **decode round** steps every decode-ready, non-cancelled, non-terminal ticket once, in submission order, through `Device::step_rows`, a ticket with sampling or logprobs included (ledger CR4: `RowArgs` carries the row's `ItemSampling` and logprobs output; the toy samples the row through `sampler_ref`, the CUDA device runs K12 per sampled row on its own logits, output counts and counter key, the session position, so a sampled row equals the same ticket alone); while decode rows are ready, each prefill run is followed by `decode_rounds_per_prefill_chunk` decode rounds (default 1), so decoding rows and their cancels advance between prefill runs. A round commits one token per participant; finish/error reached in a round wait on the ticket (`finish_pending`, `error_pending`) for its next poll. Per-row preconditions (cancel, LENGTH, context, broken session, toy `CERE_PENDING`) are checked before any launch and end or skip only that row; a failure after the first launch breaks every participant (`CERE_FINISH_ERROR`/`CERE_ERR_INTERNAL`), never a non-participant. The CUDA device runs one row through the unchanged single-row DECODE forward and two or more through `model::forward_decode_rows` (HC, projections and MoE at m = R on the `Workspace` rows plans, built by `GemmPlan::init_rows` from the instantiated single-row plans with a per-m fallback to m single-row GEMMs; PLE, GDN core, attention, lm_head and the sampler stage per row). Plain rows run as one call of m = R ≤ 16 (`GemmPlan::kMaxRows`). A speculating round's rows (`CudaDevice::speculate_rows`, at most R ≤ 16 rows, so the drafts take at most 16 rows) verify in consecutive groups in row order, each the longest prefix whose chains (draft count + 1 tokens each) fit one verify call of `layout::verify_rows` = min(16, 4 x R) tokens (`speculate_group`; batch-concurrency design note BC2, F9). Batched = single-row bit-for-bit at every m ≤ 16 (D6, BC-D2), gated by the BC0 invariance suite (`native_dev.py test --suite batch_inv`). The order of calls never changes a token (R-D1). The toy device option `prefill_chunk=N` sets its chunk.
- `models/<model_id>.json` is the model descriptor (selftune design note D1/E1, schema `schemas/model_descriptor.schema.json`): dimensions, layer kinds, slots, weights, graph segmentation, draft head and vision tower, each value naming its `config.json:` and/or `executor:<path>#<constant>` sources. `make precheck` (`scripts/validate_repo.py`) checks each executor source equals that constexpr (a literal, or the generated `gen::` constant it reads) and, where the checkpoint is readable, each `config.json` source. The build (`CMakeLists.txt`, the Makefile host build and `hip/build.sh`) generates `generated/cere_model_constants.h` (namespace `cere::gen`) from `models/<CERE_MODEL>.json` (default `qwen38-flash-next`; `native_dev.py build --model ID` sets it) with `tools/gen_model_header.py` (SelfTune ST1a; stdlib, byte-deterministic), and the kernel, model, host and research headers read their dimension constants from it, so the descriptor and the generator are native build inputs (`lock_native.py`). A library is built for one model family (ST4 S3a): the header's `gen::kFamily` / `CERE_GEN_FAMILY` come from the descriptor's `model_type` (`qwen4_exp`, `sdar`); `cuda/src/host/family.h` makes `api.cpp` refuse a descriptor of another family and, on an `sdar` library, every unsupported slot choice and feature by name. Family `sdar`'s CUDA library (ST4 S3c, `native_dev.py build --model dice-8b`) compiles the host and research sources with `cuda/src/{kernels,model,device,ktest}/sdar/` in place of the Qwen ones (no K2, P3b or Qwen kernel): `kernels/sdar/` the BF16 kernels and a cuBLASLt GEMM, `model/sdar/schedule.h` the header-only block-diffusion schedule (full prompt blocks prefilled; per decode block one denoise forward per masked position, then one commit forward storing the block's KV; a failed or cancelled call leaves the fed tokens and KV position unchanged), `model/sdar/sdar_model.*` the forward, `device/sdar/` the `Device` (one session, greedy, eager); suite `sdar_kernels` tests it on GPU0. For the DICE-8B judge (ST4 S4, `scripts/live/dice_judge.py`), `ktest/sdar/sdar_generate_ktest.cpp` exports `cere_ktest_sdar_generate`, the e2e free run of the device's schedule over its forward with one NVTX range per prompt and per decode block, driven by `tests/gpu/sdar_generate.py` under nsys; `native_dev.py build --model dice-8b --sdar-mutant causal|fp32tie` sets the test-only CMake option `CERE_SDAR_MUTANT` (`CERE_SDAR_MUTANT_<NAME>` in every TU, recorded in `build.json`), any other name or family fails at configure, and `lock_native.py` refuses such a build. `hip/build.sh` still refuses family `sdar` by name, and the host toy library of `make test-executor-host` is built for it too. `make precheck` also refuses a `gen::` name the header does not define (under a `#if CERE_GEN_FAMILY == ...` branch or in a family's own subdirectory such as `kernels/sdar/`, against that family's descriptors). The executor inventory it was drawn from is selftune-inventory design note.
- `cuda/src/model/plan.h` is the decode and draft plan (selftune design note D2/E2, SelfTune ST1b-e): `plan::kDecode`, built at compile time from the descriptor's per-layer kinds (`gen::kLayerMixer`, `gen::kLayerFfn`, `gen::kLayerPle`), lists the slots (`embed.tokens`, `embed.ple`, `mix.hc`, `attention.full` / `attention.linear_gdn`, `ffn.moe`, `combine.hc`, `norm`, `lm_head`) in today's launch order; then the fusion pass applies its registered peephole rules (one today, `hc_combine_norm`: a combine fuses the next mix's RMSNorm, except before the PLE layer). `forward.cpp`'s `run_layers` (a DECODE step and, since ST1d, every PREFILL chunk and MixedPD segment: `embed.tokens` when the call starts at layer 0, the layers of its range, `norm` and `lm_head` when it ends at the last layer), `run_rows` and `run_verify` walk it (the verify graph's segment cuts follow a layer's mlp combine), and a layer kind without a slot implementation fails the build. `plan::kDraft` (ST1e) is the same builder over the descriptor's `draft_head` layer list (one MTP layer, K13 BF16 MoE, no PLE), its last combine left unfused: `mtp.cu`'s `run` walks it (`embed.tokens` is the MTP fusion, then the layer's ops; `norm` and `lm_head` are `final_mixer` and `hot_lm_head`, run by `score_rows` on the scored rows only). Its host contract test is `tests/host/test_plan.cpp` (`make test-c`). The launch sequence is guarded by the graph suite's `tests/gpu/test_graph_launches.py` (row ST1L, `cere_ktest_graph_launches`: a CUPTI recorder of every captured graph's kernel nodes, with symbol, grid, block, dynamic smem and PDL edges, and in mode 3 of every eager launch, copy and memset too, for prefill; `cere_ktest_model_arena`: the memory plan's five arena sizes per case); `scripts/native/launch_sequence.py check <native-test-graph report>` compares a run with `tests/fixtures/native/launch_sequence.json` (recorded on `42eae64c`, ST1e: 92 cases, verify m 1-4 and chains m 2-9; prefill: dense and QSA short, one 4,096-token chunk, multi-chunk, a MixedPD-sliced call with its decode round, resume and rest, the same prompt whole, and an image prompt; and MTP drafts: `draft/chain/{graph,qsa,eager}/m2-9` and `draft/rows/{dense,qsa,eager}/r1,r4,r16`).

## Dev container: `scripts/live/native_dev.py`

All native builds and GPU tests run in the pinned bench image by digest (`bench_backend.IMAGE_ID`, never pulled), with `--network none`. Every command needs `CERE_LIVE=1`; exit 0 pass, 1 failed, 2 not enabled, 3 refused.

- `provenance`: prints nvcc, CUDA runtime, g++, cmake, ninja, glibc and the oracle package versions and writes `PROVENANCE.json` (schema `schemas/provenance.schema.json`). No GPU.
- `build`: empties `build/native/`, runs `cmake -S /src/executor -B /out -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build /out` with the repo mounted read-only, then `scripts/check_third_party.py --build-json build/native/build.json`. No GPU.
- `test --suite S`: GPU0 only; `python3 -m unittest discover -s /src/executor/tests/gpu -p 'test_S_*.py'` against `build/native/` and the A4 model (both read-only). Any skip, expected failure, unexpected success or empty run fails. Writes an internal benchmark report<utc>.json` (counts and oracle rows, no tensors).
- `probe --cache cold|warm`: GPU0 only; runs the host-built `cere-native probe` (`cargo build --release -p cere-runtime --bin cere-native`, under `$CARGO_TARGET_DIR` or `target/`) in the container against the pinned artifact; refuses below `MemAvailable` = pinned PLE bytes + 16 GiB; samples GPU0 memory every 0.25 s and fails when the executor's peak exceeds 80 GiB or GPU0 free at the peak is below 10 GiB. Writes `bench/results/native-probe-<utc>-<cache>.json`.

Container names are per checkout: `ceredev-build-<h>` (no GPU, deliberately not `cere-*`, so GPU0 preflights ignore it) and `cere-dev-g0-<h>` (GPU0), `h` = the first 12 hex of SHA-256 of the repo root's real path, so worktrees build concurrently. `test` and `probe` take `/tmp/cere-bench-g0.lock` once in `main` and require `cere-bench-g0` `absent` (bench_backend is called as imported functions). Commands, oracles and the kernel map: [cuda/README.md](cuda/README.md).

Measured (X1, `PROVENANCE.json`): nvcc 13.0.88, CUDA runtime 13.0.96, g++ 13.3.0, cmake 3.28.3, ninja 1.11.1, glibc 2.39 in image `sha256:6af86bea…a8c69`; two consecutive `build` runs at `b898e28` gave identical `libcere_executor.so` and `libcere_ktest.so` SHA-256 (an internal benchmark report). Before `-Wl,--strip-all` they did not: nvcc names each translation unit's host file `tmpxft_<pid>_…`, parallel builds get different PIDs, and those names landed in `.symtab`.

## Third-party code

Nothing is vendored. `THIRD_PARTY.json` lists every linked binary (`cudart_static`, `cublasLt_static`, `culibos` from the image's CUDA 13.0 toolkit, NVIDIA CUDA Toolkit EULA, relation `linked`) and every project whose math a kernel follows (SGLang `d4689328e` and FlashInfer 0.6.17, Apache-2.0; flash-linear-attention as adapted in that SGLang, MIT; relation `math_reference`). `scripts/check_third_party.py` (run by `make validate`) rejects an entry without license or revision, a `math_reference:` header comment under `cuda/` that names an unlisted project, and a `build.json` whose static libraries or `NEEDED` names are not listed. The M1 external backend need not implement this ABI.
